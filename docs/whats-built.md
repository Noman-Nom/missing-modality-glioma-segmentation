## J. E3 and E4 strategies (spec 0005), in progress
Milestones 1 to 3 of 5 built 2026-11-06 on branch `feat/e3-e4-strategies` (build plan steps 1 to 8, all the AI work). Fast tests on toy folders only: neither model has been trained, and no E3 or E4 number exists. The test fold is still sealed.
- `common/strategies.py`: `[strategy] name` in a config picks the hooks. `dropout` (E3) draws one of the 15 patterns per sample from `hook_rng`, each with equal chance, and zeroes its missing channels. `presence` (E4) does the same and appends 4 constant presence channels. A config with no `[strategy]` is E1.
- `common/model.py`: `PresenceUNet` wraps an 8 channel `UNet` for E4, and takes each presence channel's maximum over the patch, so the zero that `predict()` pads with cannot read as missing. `predict()` is not touched.
- `common/training.py`: `train()` and `validate()` take `image_hook`, and `check_config()` refuses an unknown strategy. `identity` is replaced by `keep_batch`. Selection stays at pattern 1.
- `0003-baseline/train.py`, `0003-baseline/evaluate.py` and `0004-missing-eval/evaluate.py` read the hooks from the run's own config, so E3 and E4 run these same scripts as commands. `experiments/0005-strategies/` holds `e3.toml` and `e4.toml`, each the E1 config plus `[strategy]`.
- `0005-strategies/compare.py`: refuses with exit 2, printing every failed rule and writing nothing, unless the three runs and evals are comparable (AC-15), and on test unless the val comparison is finished for the same runs and the same `compare_hash` (AC-16). Added after the 2026-11-06 review: on test the val comparison must also have fold `val` and the `protocol_hash` and `splits_sha256` of the test evals, and any infinite Dice or HD95 is refused (`check_rules` already refused NaN, missing cells and zero cases, and stays unchanged because the sealed E2 path shares it).
